# Database

PostgreSQL 16, schema managed by Flyway (`backend/src/main/resources/db/migration`), Hibernate runs with `ddl-auto: validate`. Timestamps are `TIMESTAMPTZ`; ids are UUIDs generated by the application.

## Migrations

| Version | Content |
|---|---|
| V1 | `users`, `user_roles` (check: REQUESTER/REVIEWER/ADMIN) |
| V2 | `data_centers`, `rack_groups` (`version` = inventory version), `servers` |
| V3 | `audit_events` with a trigger rejecting UPDATE/DELETE/TRUNCATE |
| V4 | `capacity_requests` (partial unique index on requester + `Idempotency-Key`), `placement_plans`, `plan_allocations` |
| V5 | `approvals` (unique per plan), `servers.plan_id` provenance |
| V6 | `sync_runs` |

## Integrity enforced by the database

- Unique: data center code; rack group code per data center; server hostname; one approval per plan; one request per requester and idempotency key.
- Checks: positive capacities and server attributes; server status, request status/priority, plan status/feasibility; request count 1..500; plan `allocated_servers <= requested_servers`.
- Foreign keys from servers to rack groups, allocations to plans, approvals to plans and users.
- `audit_events` is append-only by trigger. Limit: a database superuser can drop the trigger, so this is not tamper-proof.

## Relationships

```
data_centers 1─* rack_groups 1─* servers (plan_id ─▶ placement_plans)
capacity_requests 1─* placement_plans 1─* plan_allocations ─▶ rack_groups
placement_plans 1─1 approvals ─▶ users
users 1─* user_roles        sync_runs ─▶ users        audit_events (actor id/name, target, result, correlation id)
```

## Notes

- Plan content (allocations, counts, SHA-256 content hash) is immutable after creation; only status and execution outcome change.
- `placement_plans` and `rack_groups` use optimistic `@Version`; execution additionally takes pessimistic locks.
- There is no soft delete; servers are decommissioned by status.
- Dev data is created by `DevInventoryBootstrap` (profile `dev`, empty database only).
